# 京遇——可信知识增强的导览数字人与手账地图

以北京文化地图为入口，结合有来源的文化问答、导览数字人与可编辑手账。目标流程是地图选景点 → 提问 → 有来源的回答与数字人播报 → 生成并编辑手账 → 保存并挂回地图。目标流程不等于当前全部实现。

## 当前实际进展（2026-11-10）

- AI 后端：FastAPI、本地 JSON 知识与来源关联、争议记录、审核过滤、普通关键词检索、模型生成、程序检查、独立模型核验、最多一次修订、来源查询及离线测试已实现。
- 正式资料：5条天坛候选事实中，仅事实卡 `TT_QND_003` 的获批收窄表述与原文 `TT_QND_003_E01` 可发布。片段 ID 与事实卡 ID 不可混用。
- 真实模型：DeepSeek Flash 首题“祈年殿的蓝瓦是什么时候改的？”已完成生成与独立核验，两次请求成功。另保留此前一次402失败；完整测试边界见[实测报告](03_C_AI知识与接口/docs/首题真实测试结果_20261110.md)。不代表天坛知识覆盖或产品闭环完成。
- 本轮离线检查：78项测试通过，1条依赖弃用提示；没有调用真实模型，见[工程检查记录](03_C_AI知识与接口/docs/records/20261110/工程整理与同步/本地检查.json)。
- 本机前端与视觉目录目前只有占位文件；数字人成员的独立工程不在本目录，不能据此判断其未开展工作。多轮、语音、手账、业务存储与完整前端集成尚未由本后端完成。

## 当前分工

- 王宇涵：AI 后端与可信知识增强，含结构化知识、事实检索、来源/争议管理、人工审核机制、模型问答、独立核验、知识 API 和后端测试。
- 数字人负责人：人物形象、数字人平台选型、SDK接入、语音播报、口型同步及相关交互；具体平台不由 AI 后端代选。语音识别服务按双方现有约定协作。
- 前端成员：网页、地图、景点页面及模块前端集成；图片上传、手账保存/列表/详情和地图回看按此前明确的业务存储边界推进，具体路径先对合同。
- 第四位美工成员：按已确认范围做少量美术微调；不扩展为全套 UI、地图或持续零散修改。资料搜集和人工测试由团队协作。

数字人工作不因暂时没有单独顶层目录而归入 AI 后端。未来若确有共享工程，再由负责人确认放置位置；本轮不移动或提交其他成员模块。

## 前端与数字人快速对接

先阅读[AI 后端—数字人接口对接说明](03_C_AI知识与接口/docs/integration/京遇%20AI%20后端—数字人接口对接说明.md)。复用 `POST /chat`，通过全部检查后使用 `answer` 显示和播报；原文见 `evidence` 与 `GET /sources/{source_id}`。演示页面需要主动点击才发送真实问答，不在页面加载时自动调用模型。

后端启动与离线测试见[后端 README](03_C_AI知识与接口/README.md)。密钥仅配置在本机 `.env`；虚拟环境、缓存、原始运行日志与私人来源路径不进入仓库。

## Git 协作

AI 后端使用 `feature/c-ai-backend`；本次仅同步个人分支，不向 main 提交、推送或合并。其他成员使用各自确认的分支，通过评审再集成。不要整体暂存未辨明归属的文件，不提交 `.env`，不强推。仓库里的历史说明只记录当时状态，当前结论以本页、当前职责说明、正式数据与最新实测记录分别为准。
