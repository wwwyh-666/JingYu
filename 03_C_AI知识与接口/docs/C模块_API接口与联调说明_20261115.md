# C 模块 API 接口与联调说明（2026-11-15）

本文是接口速查与联调索引，**不替代**既有合同：
- 数字人对接正式说明：[`docs/integration/京遇 AI 后端—数字人接口对接说明.md`](integration/京遇%20AI%20后端—数字人接口对接说明.md)
- 接口合同：[`docs/接口合同_0.2.md`](接口合同_0.2.md)；在线结构：服务启动后 `/docs`、`/openapi.json`
- 字段定义源码：`app/models.py`；路由源码：`app/main.py`

## 1. 路由总览（当前实际实现）

| 方法 | 路径 | 作用 | 调模型 | 主要响应 |
|---|---|---|---|---|
| GET | `/health` | 服务/配置/知识库规模自检 | 否 | 服务状态 JSON |
| GET | `/spots` | 八个景点基础信息 | 否 | `SpotsResponse` |
| POST | `/chat` | 单轮可信问答（检索→生成→检查→核验→发布） | 是 | `ChatResponse` |
| GET | `/sources/{source_id}` | 查看来源与其**当前可发布**原文证据 | 否 | `SourceResponse` |
| POST | `/journal/draft` | 手账生成合同预留 | 否 | 501 `NOT_IMPLEMENTED` |

无用户鉴权、无限流、无幂等去重；默认仅允许 `http://localhost:5173`、`http://127.0.0.1:5173` 跨域。

## 2. GET /health

```json
{"status":"ok","stage":"2026-11-09-single-turn-evidence-pipeline","model_provider":"deepseek",
 "model_ready":true,"model_called":false,"spot_count":8,"candidate_fact_count":18,"publishable_fact_count":16}
```

- `model_ready=true` 只表示配置齐全（provider/name/base_url/key/timeout/tokens 全通过校验），**不代表模型可用或已调用**。
- `publishable_fact_count` = 有可发布证据的事实数，当前 16（= approved 事实数）。
- 联调排查顺序：先 `/health` 确认连接与配置，再触发 `/chat`。

## 3. POST /chat

### 3.1 请求字段（`ChatRequest`，未知字段会被 422）

| 字段 | 必填 | 约束 | 说明 |
|---|---|---|---|
| `spot_id` | 是 | `TT/GG/ZGL/YHY/JS/GWF/YHG/ZYM` | **必须由前端显式传入**，后端不猜景点；跨景点问句会 `SCOPE_MISMATCH` |
| `question` | 是 | 1—2000 字符 | 语音场景先转成用户确认后的文字 |
| `object_id` | 否 | ≤100 | 进一步限定建筑对象；与问句冲突时 `SCOPE_MISMATCH` |
| `period` | 否 | ≤200 | **精确字符串**匹配事实 period，不是自然语言年代解析，建议不传 |
| `request_id` | 否 | 1—100 | 业务追踪用，原样回显；无去重/幂等能力 |
| `session_id` | 否 | ≤100 | 当前仅回显，无多轮记忆 |
| `turn_id` | 否 | 1—1000 | 当前仅回显 |

### 3.2 响应字段（`ChatResponse`）

| 分组 | 字段 | 用法 |
|---|---|---|
| 身份 | `spot_id`、`session_id`、`turn_id` | 回显校验 |
| 回答 | `answer` | 展示与播报文本（当前无独立 `speech_text`） |
| 依据 | `fact_ids[]`、`claims[]`（含逐句 `fact_id/evidence_ids`） | 逐句追溯 |
| 来源 | `citations[]`（`source_id/title/url/evidence_ids`） | 来源面板标题与链接 |
| 原文 | `evidence[]`（`quote/locator/url/quote_sha256/usage/审核字段`） | 展示"本次依据"，与 `citations[].evidence_ids` 求交集 |
| 状态 | `check_status`、`confidence_flag`、`evidence_review_status` | 是否可播报 |
| 核验 | `verification.status`、`verification.judgments[]`、`verification.revision_count` | 逐条 `supports/contradicts/insufficient_evidence` |
| 标记 | `is_mock`、`model_called` | 是否为模拟/是否真实调用 |
| 错误 | `error_code` | 见 3.4 |
| 追踪 | `request_id`、`answer_id`、`metrics`（总耗时/检索耗时/每次调用耗时与 usage） | 联调定位与费用核算 |

### 3.3 成功判定（必须同时满足）

```text
HTTP 2xx（模型类错误映射为 503/504/502，见 3.4）
error_code === null
check_status === 'passed'
confidence_flag === 'supported'
evidence_review_status === 'approved'
verification.status === 'supported'
fact_ids 非空 && claims 非空 && citations 非空 && evidence 非空
is_mock === false && model_called === true
```

只判 HTTP 200 会把"拒答/失败"误当成功——第一轮验收中 Q2 就是 200 + `NO_PUBLISHABLE_EVIDENCE`。

### 3.4 拒答与异常

| 情况 | HTTP | error_code | 前端处理 |
|---|---|---|---|
| 正常发布 | 200 | null | 显示 answer + 来源；可交 TTS |
| 无可发布证据 | 200 | `NO_PUBLISHABLE_EVIDENCE` | 显示边界说明，不播报文化结论 |
| 景点/对象不符 | 200 | `SCOPE_MISMATCH` | 提示确认景点与建筑，不自动换范围重问 |
| 程序检查失败 | 200 | `PROGRAM_CHECK_FAILED` | 不播报候选 |
| 核验输出非法/不支持 | 200 | `VERIFICATION_OUTPUT_INVALID` / `VERIFICATION_NOT_SUPPORTED` | 不播报，不自动重试 |
| 知识库非法 / 发布中证据变化 | 200 | `KNOWLEDGE_DATA_INVALID` / `EVIDENCE_CHANGED_DURING_REQUEST` | 停止播报，交后端定位 |
| 模型未配置 / 传输失败 | 503 | `MODEL_NOT_CONFIGURED` / `MODEL_TRANSPORT_ERROR` | 按失败处理，保留错误码 |
| 模型超时 | 504 | `MODEL_TIMEOUT` | 停止等待动画，不自动重试 |
| 厂商错误/解析失败/输出截断 | 502 | `MODEL_HTTP_*` / `MODEL_INVALID_*` / `MODEL_INCOMPLETE_OUTPUT` | 不发布候选 |
| 请求结构错误 | 422 | FastAPI `detail[]` | 修正参数（此响应不是 ChatResponse） |
| 来源不可发布 | 404 | `detail.code=SOURCE_NOT_PUBLISHABLE` | 来源面板提示暂不可查看 |

失败时 `answer` 也可能是边界说明文本，**必须结合状态字段判断**再决定是否播放。

### 3.6 一次请求的模型开销

- 正常：生成 1 次 + 核验 1 次 = 2 次模型请求；
- 触发修订：最多 4 次（生成/修订各配一次核验）；
- 检索为空、模型未配置、景点不符：0 次；
- 无自动重试、无流式；浏览器取消请求不保证取消后端执行，仍可能计费。

## 4. GET /sources/{source_id}

- 无请求体、不调模型；返回 `{"source": {...}, "evidence": [...]}`。
- `evidence` 只包含**当前**满足可发布条件的原文，因此可能少于来源白名单数量；来源状态变化后可能返回 404。
- 展示"本次依据"时应与本次 `citations[].evidence_ids` 取交集，不把整页当本题依据。

## 5. 前端/数字人调用要点

1. `spot_id` 由前端明确选择（当前 UI 语义：用户选景点→提问），不要依赖模型猜测。
2. 等完整响应后按 3.3 判定；不流式，加载中显示"正在检索与核验"。
3. `answer` 原样用于显示与 TTS，不删来源限定、不改年份、不自行补句。
4. 切题/换景点时停止旧音频、失效旧请求（AbortController + 递增序号）；重播复用已有结果，不重新 `/chat`。
5. 不自动重试失败请求；失败候选不播报。
6. 示例：`docs/integration/chat-client.mjs`（`askJingyu()`/`getSource()`）、`docs/integration/chat-demo.html`（需 HTTP 托管，如 `python -m http.server 5173 --directory docs/integration`）。
7. 分机联调：后端需监听可达地址（如 `0.0.0.0:8000`），前端 `baseUrl` 填后端局域网 IP，并把前端页面的 origin 加入 `CORS_ORIGINS` 后重启。

## 6. 尚不存在的接口（不要臆造）

- 无 `/speech/transcribe`、`/speech/synthesize`、无音频上传与 TTS 返回；
- 无多轮会话接口、无历史记录接口、无用户/鉴权/配额接口；
- 无事实详情查询接口（事实信息随 `/chat` 的 `claims`/`fact_ids` 返回）；
- `/journal/draft` 固定 501。

**数字人 SDK/语音接口尚未交付到本项目**；上述缺口需在联调阶段与数字人成员按实际 SDK 再约定，本文不预设其请求体或音频格式。
