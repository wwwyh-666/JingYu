# 京遇单轮知识接口合同 0.2.0

2026-11-09实际代码合同；前端接受情况尚待确认。沿用/health、/spots、/chat和/journal/draft及原有基础字段，新增GET /sources/{source_id}。不包含多轮记忆、语音、上传、业务存储或部署。八景编号和/spots模板不变。

## GET /health

返回模型配置是否齐全model_ready、模型provider、景点/候选事实/可发布事实数量。model_ready只表示配置检查通过；model_called=false表示健康检查本身不调用模型。不能把健康检查200或配置齐全作为真实模型连通证明。

## POST /chat

请求保留spot_id、question、session_id、turn_id、object_id；新增可空period和request_id。period目前按完整字符串精确匹配，不做自然语言朝代解析；request_id最多100字符，会生成独立answer_id作为本次结果标识。session_id与turn_id只回显，不存储多轮记忆。

示例请求：

```json
{"spot_id":"TT","object_id":"TT_QND","question":"祈年殿的蓝瓦是什么时候改的？","request_id":"tt-first-question"}
```

保留响应字段answer、fact_ids、citations、confidence_flag、check_status、is_mock、model_called、spot_id、session_id、turn_id。新增：

| 字段 | 含义 |
| --- | --- |
| request_id、answer_id | 请求关联和服务端本次结果编号 |
| claims | 仅通过检查后发布的逐条文字及fact_id、evidence_ids、对象和时期；失败时为空 |
| evidence | 本次发布引用的原文、来源ID、URL、定位、哈希及审校状态 |
| verification | 自动核验状态、逐条judgments、revision_count（0或1） |
| evidence_review_status | approved表示本次检索证据满足审校门槛；no_publishable_evidence表示没有合格证据；不是生成答案获人工批准 |
| error_code | 未配置、无证据、范围不符、程序检查或模型失败等明确原因 |
| metrics | 本次总耗时、检索耗时、各次模型请求时间、实际返回模型ID、请求耗时、实际返回的数字用量 |

citations保留source_id、title、url，新增evidence_ids；由服务端从本次真实证据组装，不接受模型自填URL。claims中的evidence_ids对应evidence.evidence_id，verification.judgments.claim_id对应claims.claim_id。

### 状态解释

- confidence_flag=supported、check_status=passed、verification.status=supported：程序检查及模型核验支持本次回答。自动检查不等于人工审校，不能展示为“人工已审答案”或“保证正确”。
- 无证据/范围不符/核验不支持：不发布候选回答。answer返回边界说明，claims、fact_ids、citations、evidence为空。
- verification.status为not_run / supported / contradicts / insufficient_evidence / failed。逐条verdict为supports / contradicts / insufficient_evidence，分别对应支持、矛盾、证据不足。
- is_mock=false不单独表示成功：正式数据拒答和真实调用失败也都是false。只有测试注入的脚本模型才是true；运行环境不提供跳过审校或开启假答案的请求参数。
- model_called表示本次是否尝试模型请求；失败请求也为true。成功/失败、用量和模型名称看metrics.calls。未调用的用量为空，不填0冒充厂商返回。
- 原有mock和human_reviewed枚举仅为兼容旧JSON示例保留，当前/chat不产生这两种检查结果。

### HTTP状态

| HTTP | 条件 |
| --- | --- |
| 200 | 通过，或受控的证据不足、范围不符、程序/语义核验未通过；前端仍需读check_status |
| 422 | 请求字段、长度、ID等不合法 |
| 503 | 合格证据存在但模型未配置，或模型连接失败 |
| 504 | 模型调用超时 |
| 502 | 厂商HTTP错误、响应格式异常、空内容或截断输出等 |

以上模型错误响应仍采用完整ChatResponse，不使用假答案填充。正式无证据时先拒答，即使配置缺失也不会发请求，因此返回200和NO_PUBLISHABLE_EVIDENCE，而不是尝试连接后再报错。

## GET /sources/{source_id}

200返回`{source: Source, evidence: [Evidence]}`，用于显示来源标题、链接、原文和定位。只返回当前合格事实关联的可发布片段；待审、停用、关联失效或没有可发布原文的来源返回404，detail.code=SOURCE_NOT_PUBLISHABLE。不接受include_unreviewed参数绕过。

## 数据与发布规则

facts_*.json保留候选事实；sources.json保存来源；evidence_TT.json保存原文证据。事实、事实关联的全部来源、实际使用的证据均须approved并带审校人及日期。来源的approved_evidence_ids还必须明确包含被使用的片段编号，来源可用不扩大为整页正确。链接、事实/景点/对象/时期关联及原文哈希必须匹配。disputed事实和suspected_typo证据不进入本轮正式回答。片段usage=context_only仅供理解语境，不能成为某个事实陈述唯一的支持依据。

每次请求重新读取数据，模型完成后再次检查所用数据是否变更；改变则停止发布。2026-11-10按用户明确批准，仅TT_QND_003和S1/E01可发布；其他候选和片段保持原状态。

生成和核验是独立的两个system/user请求。核验只看相同原文、获批事实范围、问题和候选claims，不读取生成内部思考或上次核验结论。最多一次修订，修订后重新检查和核验；调用异常直接停止，不做隐蔽网络重试。
