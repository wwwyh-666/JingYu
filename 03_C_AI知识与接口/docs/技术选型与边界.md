## Python后端

FastAPI 的类型校验和 OpenAPI 适合 B 按合同联调；Pydantic 约束 spot_id、审校状态和请求长度；Uvicorn 负责本地 ASGI 启动。Django 适合完整后台但今天引入范围偏大，Flask 可用但需要另补类型合同。以上为项目适配判断，不是性能实测结论。开源框架无按次服务费用，部署主机另计。依赖已在 D 盘隔离安装，确切版本见 requirements.lock.txt；长期对外部署前还需依赖安全、认证、限流等评估，今天仅绑定本机。
官方：https://fastapi.tiangolo.com/

## 文化知识存储与检索

今天采用 UTF-8 JSON：八景景点表、八份事实文件、来源表分离，ID 可追溯，便于人工审读与版本比较。只按 spot_id / object_id / period 过滤后，使用人工登记关键词排序；同分按 fact_id 稳定排序。没有向量化、嵌入服务、模型生成或语义理解，不能解决否定问句、复杂意图或同义词全面覆盖。

建议后续确认 SQLite 作为结构化事实与来源存储；规模扩大且关键词基线不足时评估 FTS5 / 中文分词或 trigram。FTS5 的默认分词不等于中文语义检索，需要独立验证，今天不建向量库。SQLite 无数据库托管费用，适合单机小团队；并发写入及远端多人协作是后续限制。Chroma/FAISS 等向量方案会引入嵌入成本、依赖与审校复杂度，今天不采用。
官方：https://www.sqlite.org/fts5.html

待人工审校事实默认不进入可发布检索；只有显式 --include-unreviewed 才能在离线样本中看到。source_id 是本项目登记的本地标识，不冒称官网引用编号，也不代表支持性已被人工确认。
