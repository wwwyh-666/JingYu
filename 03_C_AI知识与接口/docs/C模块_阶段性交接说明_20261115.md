## 2. 现在能提供什么

1. 对八个景点各若干已审事实的单轮问答，回答带事实 ID、逐句证据、来源链接与原文片段。
2. 严格拒答：资料不足、景点不符、模型未配置、核验不通过时不会输出未审内容。
3. 可核验的运行痕迹：每次请求的检索结果、候选、问题码、核验判定与 Token 用量都写入审计 JSON。
4. 稳定的 JSON 合同，前端可直接对接（无需改后端）。

## 3. 如何启动与调用

```powershell
Set-Location 'D:\JingYu\03_C_AI知识与接口'
# 首次：重建环境（已有 .venv 可跳过）
.\scripts\bootstrap.ps1
# 启动（127.0.0.1:8000）
.\scripts\start.ps1
```

```powershell
# 健康检查
Invoke-RestMethod http://127.0.0.1:8000/health
# 一次问答
$body = @{ spot_id='TT'; question='祈年殿过去主要用于举行什么活动？' } | ConvertTo-Json
Invoke-RestMethod -Method Post -Uri http://127.0.0.1:8000/chat -ContentType 'application/json; charset=utf-8' -Body $body
```

- 模型配置：复制 `.env.example` 为 `.env`，填 `MODEL_API_KEY`；**不要提交密钥**。改配置后需重启。
- 未配置模型时 `/chat` 返回 503 `MODEL_NOT_CONFIGURED`（非伪装成功）。
- 在线接口文档：`http://127.0.0.1:8000/docs`。

```powershell

Set-Location 'D:\JingYu\03_C_AI知识与接口'
```

- `/chat` 成功判定看 `check_status=passed` + `verification.status=supported` + `error_code=null`，不是只看 200。
- `/sources/{source_id}` 只返回当前可发布原文；若返回 404 说明该来源/证据状态已变化。
- 审计追踪在 `logs/qa/qa-{answer_id}.json`（本机产物，不提交）。

## 7. 下一阶段协作需求

**与前端（成员B）**
1. 景点选择 → 传 `spot_id`；提问传 `question`；需要限定建筑时传 `object_id`，`period` 建议不传。
2. 按第 5 节成功判定决定是否展示/播报；失败不重试、不补写。
3. 展示 `answer` + `citations` + 本次 `evidence`；来源面板数据用 `/sources/{id}` 与本次 `evidence_ids` 求交集。
4. 提供页面 origin 以便配置 `CORS_ORIGINS`；分机联调需后端监听可达地址。

**与数字人（成员/数字人组）**
1. 需要对方交付：ASR 调用方式、TTS 调用方式、音频格式、播放/停止/重播接口、口型或字幕同步方案。
2. 我方可提供：已通过检查的 `answer` 文本、语速/断句建议（可选）、失败状态码语义。
3. 语音链路建议：麦克风 → ASR → 用户确认文字 → `POST /chat` → 判定 → TTS 播报 → 展示来源。
4. 在收到 SDK 前，不预设其接口路径与请求体，避免文档与实际冲突。

**待办优先级建议**
1. 8 题同轮真实回归（约 $0.004）→ 形成"8/8 当前快照"证据；
2. 数字人 SDK 到位后做端到端联调（含 CORS/分机/停止播报）；
3. 视需要补充八景事实数量与自然问法覆盖（走人工审核流程）。
