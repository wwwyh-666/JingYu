# 京遇天坛单轮问答开发说明

当前已实现受审校门槛约束的单轮流程与离线测试。正式TT_QND_003仍待审、模型尚未决定且没有密钥，所以没有真实模型问答成功记录。代码可以跑不等于文化内容已获批准，也不等于模型实际效果已验证。

## 本轮结构

1. repository.py读取当前JSON，先筛选景点、对象、时期及事实/全部关联来源/原文证据审校状态，再按关键词和少量明确的屋顶蓝瓦词形规则检索。
2. qa.py把原文、来源定位、获批事实范围和边界交给生成请求。模型只能返回逐条claims；服务端组装最终answer，避免未检查的自由文本尾部进入前端。
3. 程序检查引用是否属于本次检索，检查事实与景点、对象、时期、来源关联和可发布状态。这不等于原文在语义上支持结论。
4. model_client.py发起另一次独立请求，逐条检查原文是否支持、矛盾或证据不足。内部思考不保存、不回传给核验请求。
5. 最多一次修订，修订后重新程序检查和模型核验。失败时最终响应不包含未通过的候选文本、claims或引用；局部候选仅留本机日志用于排查。
6. 发布前重新读取数据，若原文或审校状态变化则停止发布。成功时返回原文、来源、逐条检查状态、用量和耗时。

本轮仅支持窄范围对象；关键词覆盖和对象名检查是确定性基线，不具备完整语义理解。比较多个建筑时可要求澄清，不能把它描述为通用北京文化问答。两个请求使用同一模型仍可能有相关错误，自动核验不能保证史实准确。

## 审读数据怎样处理

当前.md文件中的S1—S3“是”和C01—C05“支持”已保留并登记在data/reviews_TT_QND_003.json。来源适用、拆分表述支持、整条事实发布分别记录。正式事实正文未替换；收窄表述只保留为建议。

仍需明确的最少信息：整条事实处理结论、最终采用文字（可写采用稿中收窄表述）、团队自审人及身份、实际审读日期。本轮按团队自审办理，不要求重新填写已完成项目，不把教师记录设为程序放行条件，不代填教师审读。

data/evidence_TT.json保存E01—E06的原文、稳定编号、来源、URL、定位、原文哈希和待审状态。E04/E05仅供语境，E06原样保留疑点并设为suspected_typo，不交给模型作为回答依据。身份或日期不明确时，不将任何记录自动设为approved。

## 本机模型配置

路径：D:\JingYu\03_C_AI知识与接口\.env。该文件被Git忽略，不在聊天发送密钥。先从.env.example复制，不覆盖已有.env；修改后重启服务。当前没有创建带真实密钥的.env。

| 变量 | 作用 |
| --- | --- |
| MODEL_PROVIDER | disabled（默认关闭）、deepseek、openai_compatible |
| MODEL_NAME | 已选服务的实际模型ID，不自动指定 |
| MODEL_BASE_URL | 不含/chat/completions的基础地址，不放密钥/query参数 |
| MODEL_API_KEY | 只保存在本机的服务密钥 |
| MODEL_TIMEOUT_SECONDS | 默认30，允许1—120秒 |
| MODEL_MAX_OUTPUT_TOKENS | 默认1600，允许100—8000；限制响应长度，不是费用限额 |

接入走HTTP，不新增SDK。复用已锁定的httpx 0.28.1，将其从仅测试依赖提升为运行依赖，不改锁定版本或安装GPU包。适配器拒绝异常JSON、空内容、输出截断以及服务端错误，不打印鉴权头、密钥或厂商错误正文。

## 记录与局限

logs/qa/qa-服务端UUID.json保存请求、实际命中原文、各次候选、程序检查、独立核验结果、最终响应、调用时间、实际模型ID、各次耗时和厂商实际返回的数字用量。原始内部思考不记录；费用在未核价时为null。日志目录不提交Git，保留在本机。

本轮验收记录见docs/records/20261109。正式数据的实际响应和“临时自审副本+脚本模型”的离线完整链路分开存放。无可发布证据时，实际命中为空、候选和核验未执行，不能补成一份虚构的真实成功记录。

下一次真实小规模验收需要两个条件同时具备：整条事实和相关来源/证据具备实际自审放行记录；选定服务商/模型并在本机配置有效密钥与使用条件。当前不满足，真实调用次数为0。
